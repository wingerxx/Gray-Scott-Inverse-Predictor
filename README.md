# Gray-Scott Inverse Parameter Predictor

An **inverse parameter predictor** for the Gray-Scott reaction-diffusion model.
Given a simulator-generated final-state image (plus its initial-condition
information), the model predicts the two reaction parameters that produced
it: **`f`** (feed rate) and **`k`** (kill rate). The diffusion constants
`Du = 0.16` and `Dv = 0.08` are fixed across all data and are not predicted —
this is a 2-D regression problem.

## Design: self-consistent data

The forward simulator (`gsinverse.simulator`) is used as **both the
training-data generator and the validation tool**, so the image→parameter
mapping the model learns is internally consistent with the simulator used to
check its predictions.

- The original HDF5 dataset (e.g. `grayscott_64x64_1-1000.hdf5`) is used
  **only** to supply `(f, k)` pairs known to converge to stable steady-state
  patterns. Its stored images are ignored.
- For each `(f, k)` pair, training images are freshly generated by running
  the simulator for 1000 iterations with a random seed (multiple seeds per
  pair, configurable), forcing the model to learn seed-invariant features of
  `f` and `k`.

### Model input

Each sample is a `(3, 64, 64)` tensor at native resolution (no upscaling):

1. `U_final` — final U field
2. `V_final` — final V field
3. `V_initial` — the seeded initial V field at t=0 (encodes the seed)

Each channel is independently min-max normalized to `[-1, 1]`.

### Target

`[f, k]` — a 2-D regression target.

## Repository layout

```
config/default.yaml       # all hyperparameters, paths, model.name, etc.
src/gsinverse/
  simulator.py             # create_initial_fields, simulate_gray_scott
  params.py                # extract (f, k) pairs from the source HDF5
  datagen.py               # build & cache the (image, [f, k]) dataset
  dataset.py               # torch Dataset over the cache (+ on-the-fly mode)
  models/                   # build_model(config) factory: CNN and ViT
  train.py                 # training loop
  evaluate.py              # validation & plotting routines
  utils.py                 # device select, normalization, seeding, config loading
scripts/                   # CLI entry points (see below)
tests/                     # pytest tests for the simulator
```

## Installation

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

## Usage

All commands read defaults from `config/default.yaml`. Override any value
with `--set a.b.c=value` (repeatable).

### 1. Extract `(f, k)` pairs from the source HDF5

```bash
python scripts/extract_params.py \
    --config config/default.yaml \
    --output data/fk_pairs.npy \
    --set paths.hdf5_path=data/grayscott_64x64_1-1000.hdf5
```

### 2. Generate and cache the training dataset

Runs the forward simulator for every `(f, k)` pair (with
`data.seeds_per_param` random seeds each) and caches the results to
`paths.cache_dir`.

```bash
python scripts/generate_dataset.py \
    --config config/default.yaml \
    --fk-pairs data/fk_pairs.npy
```

### 3. Train

```bash
python scripts/train.py \
    --config config/default.yaml \
    --fk-pairs data/fk_pairs.npy
```

To train the ViT instead of the default CNN:

```bash
python scripts/train.py \
    --config config/default.yaml \
    --fk-pairs data/fk_pairs.npy \
    --set model.name=vit
```

#### Tracking with Weights & Biases

Set `wandb.enabled=true` (and `wandb login` once beforehand) to log
per-epoch train/val loss and learning rate to a wandb run, in addition to
the local CSV log:

```bash
python scripts/train.py \
    --config config/default.yaml \
    --fk-pairs data/fk_pairs.npy \
    --set wandb.enabled=true \
    --set wandb.project=gray-scott-inverse \
    --set wandb.entity=your-wandb-username
```

Wandb is off by default and has no effect unless `wandb.enabled=true`.

### 4. Evaluate

```bash
python scripts/evaluate.py \
    --config config/default.yaml \
    --fk-pairs data/fk_pairs.npy \
    --checkpoint checkpoints/best_cnn.pt \
    --output-dir checkpoints/eval
```

This runs the four validation routines:

1. **`evaluate_and_plot`** — MAE/R² for `f` and `k`, plus predicted-vs-true
   scatter plots.
2. **`inspect_random_prediction`** — predicts `(f, k)` for a random
   validation sample and re-simulates with those values for visual
   comparison.
3. **`inspect_ground_truth_simulation`** — re-simulates with the sample's
   *true* `(f, k)` as a sanity check on the simulator.
4. **`compare_simulations`** — a 3-way comparison (dataset image,
   true-param simulation, predicted-param simulation) using a shared seed
   for a fair visual comparison. Predictions are clamped to `>= 0` before
   simulating.

## Model swapping

Set `model.name` in the config (or via `--set model.name=...`) to switch
between:

- **`cnn`** (default) — a ResNet-18 backbone adapted to `in_chans=3`,
  global average pooling, and a small MLP head.
- **`vit`** — a "vit_tiny"-sized Vision Transformer configured for native
  64x64 input with patch size 8 (64 tokens).

Both are produced by `gsinverse.models.build_model(config)`.

## On-the-fly data generation

By default, datasets are pre-generated once and cached to `paths.cache_dir`.
To instead regenerate every sample with a fresh random seed on each access
(maximal augmentation, but much slower), set `data.on_the_fly=true`.

## Tests

```bash
pytest
```

Covers the simulator: Laplacian kernel sums to zero, output shapes, and
determinism under a fixed seed.
